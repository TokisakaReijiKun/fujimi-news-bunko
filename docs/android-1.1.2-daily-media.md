# Android 1.1.2：日刊操作栏与新闻图片

版本为 `1.1.2 / versionCode 25`，沿用既有包名与签名。

- 日刊更新图标放在「過去の日刊」左侧。操作栏使用独立布局，不再受任务弹窗按钮的等宽伸缩规则影响；「過去の日刊」保留完整单行文字，触摸区域仍为 44px。
- 新闻附件按目标文章定位和校验。读取某篇正常文章的图片，不再依赖其他日期所有文章的正文完整性；目标文章、附件登记、文件大小与 SHA-256 校验仍保留。
- 本次不迁移、重置或修改用户文库，不创建备份。异常文章仍保留，读取其自身内容时继续报告错误。

在专用模拟器的 1.1.1 中已复现：仅破坏另一日期的合成文章正文，当前日刊仍返回三个正常标题，但三张完整 PNG 全部加载失败（404、naturalWidth 为 0）。正常 PNG、日文特殊字符文件名和无扩展名 PNG 在无异常文章时本就可以解码，故不改文件编码或 MIME 来掩盖错误。

浏览器检查覆盖 375／390／1100px 日刊栏位置、完整文本及更新弹窗操作，并回归六视图、两阅读器和原桌面入口。图片验收检查实际 naturalWidth／naturalHeight 与资源字节哈希，包含日刊、正文、收藏列表及收藏正文。

核心回归 105 项通过，无失败或跳过；包含真实 PNG 解码、特殊字符文件名、无关坏文章隔离、目标正文错误和重复 ID 拒绝。设备及打包审计记录在 `build/qa/mobile-app-1.1.2/`。

同一专用模拟器升级后，保留无关坏文章，12 处图片均实际解码为 320×180，6 个附件 URI 返回原始 SHA 一致的字节。篡改目标正文或目标图片时仅拒绝该目标，其他正常图片仍可读。375／390px 控件位置及文本、两项设备界面用例通过。

另用 Tokyo 的真实 PC ArticleStore／LibrarySync 导出含日文特殊字符 PNG 的同步包，再用 Android LibrarySyncStore 导入临时手机目录；四条列表／详情图片路径均解码为 320×180，SHA 与 PC 原图一致。手机目录中另一日期正文损坏仍不影响这些同步图片，坏文章自身继续返回 409。证据为 `pc-android-media-sync.json`，未读写活动用户文库。
