# PC 与 Android 文库同步

这是配对后的手动双向内容补齐。两端仍使用各自的文件文库；已有文件不会因为另一端删除内容而被删除。

## 使用

1. PC 与 Android 连接同一个可信私网。在 PC 设置页的“文庫互联”开启局域网同步，保持 PC 服务运行。
2. Android 设置页选择扫码，扫描 PC 二维码；也可输入 PC 显示的连接地址和 6 位配对码。手机提示已配对后，点击“立即同步”。
3. 等待双方清单读取、内容上传和下载完成。完成状态才表示内容已落盘；有冲突或传输错误时显示部分完成及原因，可以保留已有内容后重试。

PC 管理页面继续只监听本机 `127.0.0.1`。同步是单独的私网 IPv4 入口，默认端口 `8429`，仅开放配对和文库传输接口；它不会把管理页面暴露到局域网。PC 进程重启后需重新开启同步并配对。关闭同步或解除配对会使会话凭据失效。

Windows 的同步地址从已连接的物理网卡选择，优先有 IPv4 默认网关的接口；VPN／代理虚拟网卡不会用于监听或生成二维码。更换 Wi-Fi 后关闭再开启“文庫互联”，用新二维码重新配对。

当前默认使用 HTTP，仅适用于同一可信私网；配对码不是传输加密。手机地址检查不允许公网地址、用户名、密码、查询参数或自定义路径。路由器访客网络隔离、Windows 防火墙和手机网络切换可能阻止连接。

## 内容与合并

- 文章按稳定存储标识匹配，即同一 URL 与日刊日期；无 URL 的文章使用创建时标识。传输原文、译文、假名、已登记图片/视频和完整音频。收藏状态可以补齐，并在目的端保存完整收藏副本。
- 书籍按原始 EPUB 的 SHA-256 匹配，包含 EPUB、正式目录、章节、资源和完整音频；示例按标题匹配，包含原文、译文及完整音频。
- 1.0.10 起，自定义参考声线的 `data/voices/<声线名称>.wav` 也参与同步，沿用名称生成的稳定 ID；同名不同音频报告冲突。PC 的 Kokoro／VOICEVOX 等系统声线目录随清单传到 Android，声线名称与 ID 保持一致。
- Android 设置中可以选择同步的自定义声线，以及“システム音声”中的 PC 系统声线。1.0.11 起，普通打开新闻或书籍直接播放它已有的有效录音，不因手机全局声线不同而隐藏录音；新闻和书籍共用 Media3 播放器。只有主动重读时才严格匹配所选声线，缺少对应录音会明确提示。新音频合成仍依赖 PC 模型，手机独立即时合成仍为圭太／七海。声线同步不改变当前选中项，重新打开应用保留本机选择。
- Android 公共文库根目录保留 `.nomedia`，图片、视频、音频及备份目录不应作为系统相册或音乐库内容。升级到 1.0.11 后首次打开会补齐标记，并后台重扫已有媒体以更新系统索引；不删除或移动媒体文件。图库自己的缓存、已上传云端的副本不由本应用删除。
- 目的端已有 ID 和已填写内容保留，缺少的内容补齐。不同原文、不同已有译文或同路径不同附件会报告冲突，不自动替换。本机自动阅读进度、最后阅读时间和播放位置不会被另一端带入；新导入的书籍从未读状态开始。
- 删除、取消收藏和书签的最新操作不传播；书签只在本机没有相应信息时补齐。当前没有操作时间线，也不声称提供“最后操作获胜”的双向编辑合并。
- 不传密钥、通用设置、索引数据库、模型权重、后台任务、诊断文件或未完成的音频分段。已有完整音频可传输；在另一端生成新的模型音频仍取决于那一端实际拥有的模型和依赖。

每次传输以一个文章、书籍、示例或自定义声线为单位，压缩包及展开内容均限制为 **512 MiB**，自定义参考 WAV 另限 20 MiB、1–120 秒。完整包和包内文件均校验 SHA-256，先在临时目录验证，再通过存储事务提交。中断时保留已完成项目；重试会重新核对并补齐，未完成包没有字节级断点续传。

已有内容更新前保留备份：PC 新闻在 `data/backups/sync-article-*`、收藏在 `sync-bookmark-*`、书籍在 `book-*-sync-*`，示例沿用 `example-*`；Android 使用 `data/backups/` 下的同步备份目录。出现冲突时保留双方原有内容，结果中列出原因，不以 100% 完成掩盖错误。
