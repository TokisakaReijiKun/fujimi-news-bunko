# 分来源新闻处理

六家媒体分别拥有采集、正文解析、后处理和重新翻译入口。调度层按原始来源 URL 选择模块；站点内容、标题和重定向不能改变处理器归属。已知站点解析失败时直接报告，不回退到通用网页解析。

| 来源模块 | 采集及正文职责 | 后处理顺序 |
| --- | --- | --- |
| `news_providers/nhk.py` | NHK 官网/RSS、newsweb 正文、正文图片与可用预览，排除推荐区 | 原文与假名保存 → 媒体 → 翻译保存 |
| `news_providers/asahi.py` | 朝日文章链接、会员门槛、ArticleText 等正文容器 | 原文与假名保存 → 翻译保存 → 媒体 |
| `news_providers/yomiuri.py` | 読売日期文章链接、articleBody 段落、figure 图注，排除分享提示 | 原文与假名保存 → 翻译保存 → 媒体 |
| `news_providers/nikkei.py` | 日经 article 链接、mainPaywall 与会员声明、正文段落 | 先通过付费检测，再保存原文与假名 → 翻译保存 → 媒体 |
| `news_providers/sankei.py` | 産経 article-text、article-image 和图注 | 原文与假名保存 → 媒体 → 翻译保存 |
| `news_providers/yahoo.py` | pickup 正文跳转、同文分页、正文拆段、照片图注与动态视频提示 | 全文分页校验通过 → 原文与假名保存 → 翻译保存 → 媒体 |

每个模块独立定义 `collect(source, fetch)`、`html_links(blob, base)`、`extract_page(blob, url)`、`fetch_article(url, fetch)`、`postprocess(article, extracted, services)` 和 `retranslate(article, services)`。即使部分站点现在使用相同调用顺序，也在各模块内显式维护，修改某站时不会改变其他站流程。

## 公共能力的边界

- `primitives.py` 只提供单项工具：读取 JSON-LD、正文节点转段落、图注提取、URL 校验、订阅格式解析等。它不知道站点名称，不选择正文容器，也不编排整个处理流程。
- `services.py` 只提供假名、翻译调用、原文保存、媒体保存及阶段状态等单项操作。没有公共 `run()`／`enrich()` 模板流程；调用顺序、翻译和媒体的等待预算由各来源的 `postprocess` 决定。
- 网络下载与密钥处理仍由基础服务提供，保持 TLS 校验、私网限制、超时和脱敏；文件写入仍走 `ArticleStore`。这些基础设施不应复制六份。
- `custom.py` 仅处理用户配置的其他域名，保留 RSS/Atom/RDF 和简单公开正文兼容；六家已知来源不会回退到它。

## 调度与兼容

日刊分为严格的三个阶段：

1. 候选：每个来源独立调用 `collect`，最多验证 5 个候选。候选必须完成来源归属、正文和付费／分页校验；会员、无效和错误分页候选只计数，不写入文章目录，也不进入任务错误列表。
2. 选择：候选阶段结束后，先从公开候选满足每个来源的最低篇数，再轮流补足每日目标。当天已有有效文章保留并参与配额，不重新后处理。
3. 后处理：只对最终入选且尚未保存的文章按来源模块执行 `postprocess`。各模块自行决定保存原文、假名、翻译和媒体的顺序。

日刊调度只负责候选选择、来源配额、任务隔离和最终汇总。选择时先从六个来源各保留 1 篇，再从剩余公开候选中随机补足每日目标。来源列表读取失败或最终后处理失败才进入 `errors`；来源列表识别会员锁图标及重复 URL，正文防漏标诊断保存在 `candidate_stats.<来源>.reasons`。候选验证不限制为连续失败 3 次，因为选择前必须检查每个来源最多 5 个候选；来源错误不会阻塞其他来源。缺少来源时维持 `partial`。手动网址导入、修复脚本和重新翻译也走同样的来源分发。

`news_sources.py` 保留默认来源、配置迁移和旧调用接口；`article_extraction.py` 仅保留解析接口与错误类型的兼容导出，已移除统一解析流水线。现有 API、目录及 `article.json` 格式兼容；新处理结果记录 `source_key` 与 `extraction_version=3`。本次不批量重抓或改写历史文章。

付费或分页校验必须在任何入库／翻译之前完成。翻译超时保留已采集原文；重新翻译失败保留先前译文并报告错误。中止使用原有任务检查，不能因切换来源继续写入被取消的任务。

## 验证

朝日正文容器内的 p、h2、h3 按文档顺序提取，保留标题层级，正文与标题中的关键词链接只保留文字；图片位置按包含标题的段落序列计算。容器外的栏目标题、推荐区和会员提示仍排除。

读卖在 `p-main-contents` 内按文档顺序提取正文段落与 h2/h3，记录标题层级，并按包含标题的段落序列计算图片位置。推荐区、分享区不进入正文；二级标题保留粗体与左侧深色竖线。

日经普通资料框保留 `<br>` 分行；只有真实标题型目录框使用标题竖线。正文超链接以字符区间和 HTTP(S) 地址记录，假名生成时转义地址并生成安全链接。点击或键盘激活链接不触发段落朗读。

Yahoo 正文段落内嵌的推荐图片链接只移除该链接，保留同段首段正文，随后按空行拆段。日经无 h2/h3 的 `container_c1tzahnc` 记录为 `box-plain`，保留边框及普通正文字体，不生成目录标题竖线；含真实标题的目录框继续保留标题样式。

NHK 的 `markedLead`／`markedBody` 经标题、图片、分隔线及容器标记归一化后与同篇 `articleBody` 校验，随后按顺序提取标题和正文图片。`nw--link-*` 相关阅读卡片整体排除，不计为正文图片；只保留正文容器内容，不执行站点样式。图片记录插入位置，`img.web.nhk` 图片用官网匿名阅读会话下载到本篇 `media/`；二级标题按原站加粗放大。

朝日列表识别金钥匙容器 `c-icon--keyGold`、`icon__keyGold.svg` 和付费图片 alt，并关联标题旁的同篇标记，排除重复 URL。不展示会员标识的 `p-breaking__List` 速报区不作为候选入口；正文验证另检查主标题区域的 `/news/gold.html` 付费标记，拒绝可见摘要。推荐文章的付费图标不影响当前正文。

产经列表阶段排除 `有料会員記事`、`img_lock-gold.svg` 和 `paid_members` 标识，并剔除同一 URL 的无标识重复链接。正文阶段另检查主文章的 `paid_members` 类和文章头部锁标识；排行榜、推荐区其他文章的锁标识不影响当前公开文章。

日经标题限定在主文章内，正文优先使用 `data-track-article-content`。框内换行文字作为完整段落保留，`paragraph_kinds` 记录正文、标题和框类型，`paragraph_formats` 只保存加粗字符区间，不复制正文或原站 HTML。假名生成时校验区间并输出安全的 `strong` 标记，阅读器保留框线、换行和标题层级。重新翻译不改动这些格式。

日经正文中的官方 Brightcove 播放器仅用来解析媒体：后处理阶段读取公开播放器配置与 Playback API，验证同一视频 ID，选取 32 MB 内的公开 MP4 保存到文章 `media/`。不持久化播放器读取参数或临时签名 URL，不再用远程 iframe 冒充下载。失败时保留明确媒体警告。

单个日经节目保留播放器标题和官方封面。浏览器读取本地媒体元数据后，仅当无视频画面且时长有效时使用 `static/main.js` 中的封面式播放器；普通视频保留原生控制。播客支持播放／暂停、静音、音量、拖动进度、倍速和浏览器全屏，离开文章时停止播放。封面和音频均从已登记的本地附件加载。

NHK 新版 HTML 只包含摘要和推荐列表，禁止用整个 `main` 作正文。`fetch_article` 从官网公开 API 读取并验证文章 ID、canonical 和完整 `articleBody`；若需要海外阅读确认，先检查官网地域结果，仅海外使用官网无账号流程，会话只在本次请求内存在。不会声明日本国内订阅、修改网络地域或把摘要冒充全文。标题、正文、图片和视频只取该篇 API 数据，排除 citation 推荐内容。

NHK 视频后处理阶段用匿名会话领取官网短期播放令牌；令牌只在内存使用。HLS 按 HTTPS 下载已结束的有限分段，总量不超过 32 MB。标准 AES-128 使用原站公开返回的短期分段密钥，密钥仅存临时目录并随合并结束清理；不支持 DRM。ffmpeg 只读取临时本地文件并生成 MP4，禁止其访问网络；需要 PATH 中存在 ffmpeg。原站授权失败、403、地域限制或 DRM 流直接报告“未下载”，不存播放器 URL。朝日正文图片支持仅有 `srcset` 的 figure，保留 figcaption；标题取主文章的 h1。

`tests/test_news_providers.py` 覆盖六家规则隔离、各自入口归属、不同后处理顺序、日刊六来源分发、手动导入、修复、重新翻译、媒体访问、付费拦截和 Yahoo 错误分页。测试只使用本地夹具与模拟翻译，不调用真实付费 API。原有解析、来源、日刊中止及存储测试继续运行。

## 2026-09-10 采集修复

- 日经列表锁图标通过 alt/aria-label 识别，重复出现的同一会员 URL 一并排除。`mainPaywall` 也用于公开文章末尾推广，必须结合同一文章的匿名未锁定状态区分；真正会员提示、JSON-LD 付费声明或锁定状态仍拒绝。
- 朝日新版正文限定在 `main#main > div.nfyQp`，不读取整个 main 中的作者、推荐和订阅区。
- NHK RSS 的 HTTP 链接转为 HTTPS；超过七天的回退 feed 拒绝用于日刊。
- 请求保持 TLS 验证、逐跳公开地址检查和体积限制；暂时 HTTP 错误和连接失败最多三次尝试。重试次数不改变每来源五个候选的上限。
- 日刊终态在数据库保存结束后才发布；重启不清空失败记录，源站请求失败不冒充公开候选不足。
