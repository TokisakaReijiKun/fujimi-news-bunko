# 按路径和大小增量同步实施计划

用户要求：提高同步效率，现有文件以对应路径和大小比较，不做内容哈希。只改同步通路，保留普通阅读的数据格式和行为；不迁移、备份或清理活动文库。

1. PC `LibrarySync` 与 Android `LibrarySyncStore` 生成轻量清单：实体稳定 key、路径、大小、收藏状态；不读取媒体或 EPUB 计算摘要。控制元数据不因本机 ID／进度的大小差异触发同步。
2. 手机根据两端清单筛选差异。没有差异则零内容传输。差异包使用 version2、完整路径大小清单和 included 列表，仅传缺失／不同大小文件及控制元数据。导入省略文件从本机对应实体重用，保留现有补齐、冲突与进度处理。
3. PC 增加配对后的 POST `/api/sync/v2/pull`，接收目标已知路径大小。两端移除同步包与内容的 SHA 生成／比较，接收时核对实际长度。原包名、配对和私网边界保持。
4. 相关测试先复现旧行为，再检查清单无大文件读取、同路径同大小跳过、差量附件、拒绝路径越界／长度错误。运行 Python 全量回归和 Android 核心、设备测试；使用隔离 PC 文库与模拟器完成首次、重复、新增附件三轮实测，记录传输量及耗时。
5. 构建同签名 Android 1.1.7，并仅替换 PC 包内本次受影响后端模块。完成包核验后更新客户端；保留其他页面、模型和正式文库。
